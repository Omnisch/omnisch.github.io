本地模型学习笔记

发表于 2026-09-14 分类于 luon

我的配置：

  • RTX 5070Ti
  • 16GB 显存
  • Python 3.11
  • CUDA 12.8

Checkpoint 模型

Checkpoint 指基础模型，也就是一个已经训练好的完整模型权重文件。一个 Checkpoint 模型通常包含三个核心部分：

  • U-Net：核心去噪网络，从随机噪声一步步生成图像；
  • CLIP：对比式视觉语言预训练模型，把文字提示词转换成模型能够理解的语义向量；
  • VAE：变分自编码器，负责在潜空间 (Latent) 和数据之间编解码。

现在大部分模型的格式都是 .safetensors，这是 Hugging Face 开发的一种模型权重存储格式。Hugging Face 不仅是全球最大的开源 AI 社区，也是 AI 行业标准制定的重要参与者和推动者，常被称为“AI 界的 GitHub”，目前共享超过 300 万个模型。下文的 Checkpoint 模型都可以在 Hugging Face 上找到并下载。

ComfyUI 在初次使用时可以下载一个 Z-Image-Turbo 模型。Z-Image 和 Z-Image-Turbo 都是阿里云通义旗下的开源图像生成基础模型，支持生成包括写实、动漫在内的多种图像风格，主要优势为轻量、快速——Z-Image-Turbo 可以 8 步出图。

Qwen-Image 是通义千问团队研发的 200 亿参数的图像生成基础模型，以文字渲染和图像编辑能力见长。

此外还有 FLUX.1、FLUX.2 等图像基础模型，但我尚未测试，也就不再赘述。

训练 LoRA

生图任务要用上 LoRA 大概需要这么几步：建立数据集、标注、训练以及生成。

可以利用各种抓图的插件或者脚本快速建立数据集。我使用了两种第三方插件，分别是针对 Pixiv 网站的 Pixiv Batch Downloader (PBD) 和更通用的、可用于 Danbooru 网站的 Pixiv Downloader。都可以批量爬取同一作者或同一标签的图片，无需多做介绍。

在进入标注环节之前，需要知道“Booru”这么个东西。根据定义，Booru 是一类在线图像板，旨在利用协作式标签系统，对用户提交的大量图像进行托管、归档和分类。最有名的、规模最大的 Booru 应该是 Danbooru，保有数量超过 5000 万张、大小超过 60 TB 的各种格式的图片；此外还有 Gelbooru、Yande.re、Konachan 等。

A booru is a type of online imageboard designed for hosting, archiving, and categorizing large collections of user-submitted images using collaborative tagging systems.

标注环节我使用的是桌面应用 Booru Dataset Tag Manager Plus，fork 自 Booru Dataset Tag Manager，支持用本地 ONNX 推标或调用 LLM 标注，还附带许多处理和预处理功能。我选择了 [WD14] eva02-large v3 作为推标的模型，v3 优于 v1 / v2，训练数据和标签体系有所更新，eva02-large 模型较大，准确率优先。为文件夹中的图片自动标注之后，可以人工再清洗一遍，因为还是可能有不准确或者漏写的标签，这些都可能影响最终 LoRA 的效果。

训练环节我使用的是 OneTrainer，支持基于主流模型（诸如 Z-Image、Qwen Image、Stable Diffusion 等）的一站式训练。在我的个人电脑算力下，50 张图需要约 30 分钟的训练时间，100 张图需要约 1 小时的训练时间。对于同一作者同一画风的训练，我测试得到的效果较为出色；而杂图的最终呈现不尽人意，因此下文主要总结画风训练。

开始使用 ComfyUI

ComfyUI 是一个基于节点工作流的图形用户界面工具，完全开源，被广泛认为是面向专业创作者的“AI 创作引擎”。在 ComfyUI 中可以获取到很多现成的工作流，并按照提示直接下载需要的模型。

现在已经有直接以 ComfyUI 工作流为研究对象的 ACL 论文：例如 2026 年 ACL Findings 的 ComfyUI-R1 和 ComfyFlow，前者研究自动生成 ComfyUI 工作流，后者建立了 ComfyUI workflow generation benchmark。

ComfyUI 有许多用户创作的扩展包，比如 Impact Pack、Easy Use 等，其中有不少都是 QoL 节点，可以为快速搭建工作流节省不少时间，但有时也会牺牲一些灵活性。我比较看重的是这些扩展包中的 XY Plot 功能，可以生成一批微调参数的图像，然后列出一张大表便于对照。下文的二维表图都是基于 Easy Use 提供的节点渲染出来的。

针对二次元（动漫）画风，也有一些 Checkpoint 模型可供选择，比如 SDXL、Animagine、Illustrious、Pony、Krea 2 等等。可供选择的模型太多，我直接让 AI 帮我挑选了两种：Animagine XL 4.0 Zero 和 Illustrious XL 2.0，前者“served as the pretrained base model”，非常适合作为训练的基础；后者有相当大的基础模型生态，也是目前“最稳妥”的选择。这两种模型都属于 SDXL 系，提示词都更推荐使用 Booru 式的标签罗列而非自然语言，因为标签罗列更符合这些模型的训练分布。

至于 Anima / Krea 2 这种“新一代”模型，就留给在玩 Anima Lora Studio 这个端到端流水线产品的时候再体验吧。

下面是两种 Checkpoint 在同一正负面条件、同一分辨率、同一噪声种子……控制变量的表现对比。横轴是 LoRA 强度，纵轴是 CFG，但现在说这部分还太早。总之这两种模型表现都不错，没有绝对的优劣之分。

虽然二者都带个 XL，是同一个系的模型，但 LoRA 还是不太通用的，能跑，但效果大打折扣，以至看不太出来。所以不可得兼，我就选了我看着更顺眼的 Animagine 做进一步的探索。请原谅我给所有生成图片都打上水印，因为毕竟是未经作者允许做的训练，我不会上传到其他地方，也防止这些图片被使用。

K 采样器

K 采样器 (KSampler)，是 ComfyUI 中的一个核心节点，负责在潜空间中执行去噪采样。这里的 K 指一个第三方库 k-diffusion。关键的参数有：steps、cfg、sampler_name、scheduler、denoise。

  • steps 控制去噪的步数，前面也提到像 Z-Image-Turbo 这种模型可以只需要 8 步甚至更少就能出图。步数越高，一般意味着图片的细节越有可能被打磨，整体质量也就越高，但有边际效应，从 30 到 60 步可能效果显著；但从 60 步到 120 步可能区别不大，白白耗费时间。根据我的经验，30 步基本能看，50 步可能只有手指画不好，到 80 步算是“最高画质”了。
  • cfg 是我误会了好长时间的参数。我一度以为它是 Config 的缩写，然而实际上是 Classifier-Free Guidance Scale，用于控制文本提示词对生成过程的影响程度。从下面的诸多例子中可以直观看到：值越高，生成的图像越严格地遵循提示词，但同时带来色彩失真、画面过曝；值越低，图像越有自由发挥的空间，但画面普遍偏灰。
  • sampler_name 是去噪所使用的具体算法，不同的采样器在速度、收敛性和最终呈现上有显著差异。euler 是非常简单的算法，求解常微分方程速度快且稳定；dpmpp_2m (DPM++ 2M) 通过更精确的数值计算加速收敛，边缘干净；res_multistep 的累计误差更小，有显著的结构一致性优势。此外，ancestral 和 cfg_pp (CFG++) 是两个完全独立的后缀，前者代表祖先采样，会让原采样器在去噪的每一步都注入随机噪声，使得在相同条件下，w/ 与 w/o 的生成有明显差异；后者解决了当 cfg 值很低时引导失效的问题，但反过来，这些采样器也需要在非常低的 cfg 值下才能正常运作。
  • scheduler 是调度器，决定了去噪的节奏与步长，比较常用的有 karras、exponential 和 normal 等。
  • denoise 其实是一个包装其他参数的参数，它与 steps 共同决定了 start_at_step。如果 steps = 20 且 denoise = 0.75，那么相当于 start_at_step = 5，也就是从第 5 步开始去噪，走 15 步。这样会保留原 latent 的一些信息，从而实现图生图。

画风训练

训练画风 LoRA 比训练角色 LoRA 乃至概念 LoRA 似乎要容易一些。LoRA 有两个参数，模型强度和 CLIP 强度。通过调整模型强度，可以在 Checkpoint 画风和目标画风之间过渡。模型强度的数值也可以大于 1，但通常超过 1.3 之后就会出现畸变，无法维持人形了。理论上模型强度的数值也可以小于 0，但对于画风迁移来说肯定没什么用。至于 CLIP 强度，OneTrainer 默认应该是不训练 CLIP，所以调整这个数值没有用。下面是我用不同画风的数据集训练出的四个 LoRA。

降噪与画风迁移

前面提到，修改 denoise 可以实现图生图。加载图片后，用 VAE 编码成 Latent，然后代替文生图任务中传给 K 采样器的空 Latent，再降低 denoise 值，即可得到一张跟原图整体看起来差不多的、经过画风迁移的新图。下面是从 denoise = 0.2 到 denoise = 0.99 的效果对比，数值越小，越像原图；数值越大，越是全新的图。

即使提示词中限制了水印的出现，在低降噪（denoise <= 0.4）的情况中依然无法完全消除原图的水印。下面同样给出其他几个 LoRA 的迁移效果。

实际上，如果把 denoise 拆出来，得到 start_at_step 和 end_at_step 两个参数的话，还可以级联两个 K 采样器，让第一个走几步，再交给第二个，这样可以用两种不同的模型先后去噪，在保留第一个模型绘制的大致结构的基础上，添加第二个模型绘制的细节。其实也相当于不用垫图、内部消化的画风迁移。下面是两个 K 采样器级联的控制变量的效果。
